# 迁移流程与验收

适用于资源模组的主体迁移。有 `mod.lua` 执行逻辑、运行脚本或外部依赖时，另读 `script-migration.md`；具体故障读 `troubleshooting.md`。这些步骤是工作顺序，资源字段以当前版本实际定义为准。

## 1. 保存原包与建立映射

记录原模组 ID、作者、许可、支持版本、`mod.lua` 参数/回调，以及资源类型和依赖。对有许可证限制的包保留声明；本地转换与再分发分别判断。需要证明原包未改动时使用盘点脚本的 `--hash`，后续比较源文件哈希。

设置三个独立位置：原包、修复/转换副本、最终模组。为最终模组选用独立 ID，避免覆盖原版或已订阅模组。不要直接在原包或游戏原版资源中批量替换。先把全部将生成的路径列出来，检测大小写、Unicode NFC 和扩展名转换后的冲突。

## 2. 使用官方转换器

TF2 常见布局为 `mod.lua + res/`，TF3 使用 `mod.json + content/`。优先使用官方 Model Editor 的二代模型转换，使模型、材质和元数据进入当前原生格式；当前原生模型声明 `version = 2`。转换成功后仍需检查依赖、节点、编组和显示信息。

CR200J 使用过的临时布局和输入前缀示例：

```text
source_mod_id/
  mod.json                  # 可由当前编辑器创建临时模组定义
  content/
    res/                    # 原包 res 的修复副本
      models/model/vehicle/train/...

Bulk Convert 前缀：source_mod_id::/res/models/model/vehicle/train/
```

这里只是已验证的车辆转换入口，不能把 `vehicle/train/` 用于所有模组。按当前编辑器实际资源解析规则选择路径。先用一个模型确认来源、输出位置、资源类型及目标模组，再执行批量转换。不要将原生 version 2 模型重新当二代输入。最终包只收集原生输出与需要的资源，不包含这个临时 `content/res/`。

编辑器启动和用户数据位置优先从安装文件、现有配置及当前官方文档确定，避免套用其他平台或二代的路径。修改配置前保留原文件；`staging_area` 中同 ID 副本可能遮蔽手动安装/订阅版本，检查实际生效来源。

## 3. 重建三代定义与引用

按当前模组定义编写技术配置 `mod.json` 和展示信息 `_metadata/modinfo.json`，需要本地化时补充 `strings.json`。保留作者和版权，不沿用 TF2 的定义字段作为三代 schema。当前主要约束包括：modId 使用小写字母、数字、下划线；revision 从 1 起；展示名称最多 32 字符，summary 最多 100 字符，两者均无换行；严重度使用合法枚举；新增可运行车辆不是仅改变外观的 cosmetic 模组。车辆标签从官方列表选择，例如 `Locomotive`、`Wagon`、`Multiple Unit`，不要自行发明 `Train` 标签。

展示封面另迁移为 `_metadata/0.png`，原包 `image_00.*` 或 `workshop_preview.*` 不能仅复制到旧位置。图片保持原比例和作者标识，官方建议 1920×1080；缺图、转换及管理卡片验证见 [模组封面迁移](mod-cover.md)。

资源文本使用 UTF-8 无 BOM。官方文件命名指导使用 `a-z`、数字、`_`、`-`，避免空格及非 ASCII 字符；保留当前资源类型规定的扩展名及官方 UI 图标变体规则。对旧包中的中文/空格路径作显式映射，更新全部文件引用。引擎能读旧名称不等于符合发布规范。节点名称是模型内部标识符，不属于批量文件改名范围。

引用要按字段和资源解析器判断，而不是把所有字符串拼接到同一个文件夹：

| 引用形态 | 含义/检查方式 |
| --- | --- |
| `/path` | 当前模组 content 中的根路径 |
| `::/path` | 三代原版资源根路径 |
| `other_mod_id::/path` | 外部模组资源；记录真实依赖 |
| `tex/a.dds`、`::tex/a.dds` | 相对形式；按所属资源字段的基准位置解析 |

不引入 `../` 路径，也不写本机绝对路径到模组定义。原版资源可在安装资源包中存在，不一定是磁盘上的裸文件。索引资源包时建立资源名别名：`.mu.lua → .mu`、`.snd.lua → .snd`、`.trf.lua → .trf` 等；Lua/Teal 是部分资源的物理包装扩展名。只按类型去掉包装扩展名，不能把任意 `.lua` 当作同名数据资源。

## 4. 处理车辆、编组与纹理

以原包为基准比较容量、速度、功率、质量、可用年代等；官方转换可能改变单位，比较语义值。不要为消除验证提示而随意改变性能。

三代铁路车辆的车轴引用需要指向转换后节点名称。逐个检查参与车轮动画的 LOD 是否包含所有节点；`transformatorConfig.skipFromLod` 表示从哪个零基 LOD 开始停止该变换，依据实际树结构计算。铁路司机类别使用合法 `RAIL` 定义；其他车辆类型不能照搬。分组/variant 引用必须对应真实模型，空字符串和旧包中的悬空引用需清理或说明。

固定编组转为三代资源时逐车比较数量、顺序、模型和朝向。显示名称不决定实际数量；尾端动力车的根变换可能已经旋转，再翻转会改变原行为。需要改变编组时另说明修改。

转换纹理前按材质用途分组：漫反射、法线、MGA、发光和透明资源的压缩/色彩语义不同。优先使用官方编辑器导入、保存及转换。自定义转换器需要核实 DDS 头、压缩格式、alpha、通道和各 mip 数据。CR200J 使用 BC5 法线、BC1 不透明纹理及 BC3 透明纹理，但应按当前 shader/编辑器要求确定，不是全部资源的固定配方。详见 `troubleshooting.md`。

## 5. 分层验证

1. **静态**：定义有效、路径大小写一致、资源及原版依赖可解析；网格索引在界内、各索引区符合布局；DDS 完整；动画节点存在；编组与原包一致。脚本同时核实 API、导入、参数、持久化状态。盘点脚本仅提供线索，不能宣称这些检查全部通过。
2. **编辑器**：对目标模型全量运行当前编辑器校验，保存版本和日志；预览代表涂装、透明部件、开门/车轮动画以及 LOD。分别记录工具崩溃、资源错误和性能限制。完整验证仍有错误时写“失败”，另外说明能加载/已预览的范围。
3. **游戏**：用户允许时才按本次范围实际加载、启用、购买和运行；年代选择应覆盖车辆可用范围。有脚本时检查初始化、更新、事件、存档重载和参数改变。没有实际完成就写“未运行”。
4. **Windows**：确认目标游戏/API/原版资源版本与开发环境相容，实际检查包的加载、购买/运行及脚本。macOS 原生编辑器检查、静态路径检查都不能替代这一步。

优化远景需要真正降低几何/绘制成本并检查外观；不以删除远景 LOD、放宽日志判据来掩盖超限。检查阈值以目标版本为准。

## 6. 打包与报告

ZIP 内只有一个模组根目录，根下直接是 `mod.json` 和 `content/`；排除临时转换树、无用保护辅助模块、开发日志、`.DS_Store`、`__MACOSX` 和符号链接。保留所需合法脚本和依赖，不能把“清理辅助模块”当作删掉所有 Lua 的理由。打包后校验条目路径、全部 CRC，并生成 SHA-256。

跨平台检查不能只看 ZIP：确认资源文件名与引用完全一致、无依赖本机路径、无只适用于某系统的 DLL/可执行程序；检查原版资源版本以及非 ASCII 路径的兼容风险。纯资源包可以共用，平台插件/字节码支持需独立验证。

迁移报告使用项目所需的简洁格式，至少记录：源包与目标版本、保留/修改内容、缺失资源的替代、验证证据及未运行范围、剩余错误、安装/继续验证方法。输出测试包可以保留未解决问题，但不能描述为完整通过或可发布版本。
